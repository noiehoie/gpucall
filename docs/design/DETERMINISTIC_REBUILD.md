# 決定論によるgpucall再構築

更新: 2026-09-05。所有者は新規実装と必要な既存gpucallの停止を許可。
新しい独立実装は `next/`。既存の未コミット作業を保存するため旧ツリーは保持する。

## 最上位の契約

仕事・品質条件・予算・期限・主権条件を受け、適合する検証済み供給の中から
仕事全体の推定費用を最小化する。制御判断はすべて明示的な規則で行い、LLMを呼ばない。
モデルの推論出力は検査対象であり、権限・予算・規則を変更する入力にはならない。

## 初回の完成条件

- 独立してインストールできるAPI/CLIと、永続ジョブ台帳。
- 同じ依頼・規則・観測スナップショットの再生で同一計画。列挙順・時計・環境に非依存。
- 金額は整数micro-USD。並列要求と再送で予約・支出を二重使用しない。
- 検証証跡は実行構成と品質プロファイルのハッシュに依存。他の設定変更で失効させない。
- 古い価格、失敗した最新検証、未実装の秘密保持保証、予算超過はfail-closed。
- infer/visionについて、実行・出力検査・成果物確保・回収・精算まで一巡する。
- 実行開始の意図を外部操作前に記録。開始結果不明時に無条件で再投入しない。
- 中断・再起動・キャンセル・回収失敗をfixtureで再現。回収未確認では予約を解放しない。
- 実支出不明をゼロと記録しない。保守的な予約額計上と実請求額を区別する。
- ローカルfixtureと実GPU実行を明確に区別。課金実行前にfixture試験を完了する。

## 保証の限界を型で表す

品質の認定は指定した評価資料と検査規則の範囲。文章の美しさを自動保証しない。
Modalについて絶対請求上限・TEE・物理消去を保証しない。strict hard budgetやattested要求は
対応する保証が実装されるまで拒否。明示的なreserved契約は予算予約による制御を意味する。
回収レシートのprovider_terminatedは、プロバイダー内部のログやバックアップの不存在証明ではない。

## 実装境界

`models` = 型、`kernel` = 純粋判断、`store` = 原子的台帳と成果物、
`runtime` = 永続状態機械の効果実行、`providers` = fixture/Modal、`api`/`cli` = 同じジョブ操作。
学習・LoRA・MCP・追加プロバイダーは究極の設計範囲として残るが、未実装を対応済みと宣言しない。
